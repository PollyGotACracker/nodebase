# Lint 스키마

## 적용 기준

작업 전에 공통 지침의 경로 목록에서 폴더 구조, 파일명 규칙, frontmatter 규격, Markdown 링크 규칙의 원문을 읽는다.

## 구조 확인

1. `wiki/`를 OKF bundle 루트로 검사한다.
   `raw/`와 저장소 운영 자료는 OKF 형식 검사 범위 밖에 둔다.
2. 목차와 실제 문서 목록을 대조한다.
3. 문서 배치와 예약 파일 이름은 폴더 구조와 파일명 규칙으로, 목차 형식과 frontmatter는 frontmatter 규격으로 확인한다.
4. 일반 문서의 YAML 파싱과 비어 있지 않은 문자열 `type`을 확인한다.
5. Markdown 링크 규칙과 frontmatter 규격으로 링크, `sources[].resource`와 주장별 각주 연결을 확인한다.
6. 선택 메타데이터는 값의 형식과 실제 근거를 확인한다.
7. 위키링크와 `.mdx` 사용을 점검한다.
8. 고아 페이지와 끊어진 링크는 지식 품질 항목으로 구분한다.
   고아 페이지는 목차와 로그를 제외한 다른 페이지에서 참조하지 않는 문서이다.
9. Git 이력과 존재하는 `log.md`에서 최근 변경을 확인한다.

## 내용 점검

1. 상충 주장은 각각 검색하고 출처와 적용 조건을 대조한다.
2. 작성 및 검증 시각과 원본 변경을 대조해 재검토할 문서를 찾는다.
3. 메타데이터가 없으면 본문과 Git 이력에서 확인한 범위를 보고한다.

## 정리 제안

1. 근거가 있는 중복 병합, 누락 보완, 형식과 링크 수정, 내용 재검토를 제안한다.
2. 원본 보완은 제안으로 기록하고 `raw/`는 보존한다.

## 진행 방식

1. 수정과 삭제 전에 대상, 변경 내용과 검증 방법을 제안한다.
2. 승인한 범위를 적용한 뒤 같은 기준으로 다시 검사한다.
3. OKF 형식과 내용 품질 결과를 나누어 보고한다.
